## Loaded by the Embed Player iframe (https://www.tiktok.com/player/v1/{id})

GET https://www.tiktok.com/player/v1/7245648559981350186 (no query params)
  -> 39,912 bytes of HTML shell (sha256 d871a31bb36531d15f2ec8a4ac1eb376921551e1fe6bc993a84249d51399da38)
  -> references 22 further <script> tags: the privacy-protection loader, a webmssdk build,

     "tea.pre.js" (TikTok's own analytics SDK) and a "log-sdk/collect" analytics collector.

https://.../tiktok_4d_playback/static/js/lib-react.b24368ee1a.js
  -> 143,429 bytes (sha256 0a6c9aea8dd15a6c9c1f65eb69631fc35c108b413f8769692d667d44d6a137a3)
  -> one chunk of many; the full player bundle (lib-react + lib-router + lib-polyfill +
     builder-runtime + route-manifest + 9 async chunks + ItemPage) was not fully summed,
     but lib-react alone exceeds the entire /player/v1/ HTML shell by 3.6x.

## Bottom line
Neither embed mechanism is "an iframe and a video file." Both pull TikTok's own React
application, a device-fingerprint SDK (webmssdk, ~220 KB either way), and multiple telemetry
SDKs (Slardar, TEA, a log collector) as a precondition of rendering anything, before any
video byte is requested and regardless of whether autoplay or hover-play ever fires.
